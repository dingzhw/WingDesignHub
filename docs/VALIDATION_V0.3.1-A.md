# V0.3.1-A 数据治理专项验收

状态：2026-11-18 软件专项验收通过。代表产物、资源控制、恢复和最终受影响模块验证完成。数字软件版本维持 0.3.1，专项代号 V0.3.1-A。

本版服务“需求→总体方案→保存重开”的主线，保持物理模型、任务、离散和收敛条件。没有重新运行完整总体迭代；本轮证据是实际已有代表产物的一致性与资源控制验证。V0.3.2 接续计算提速。

## 实现

- 外部程序的 stdout/stderr 合并后由读线程有界流式写入。默认 8 MiB，调用方可显式指定；超限终止所属进程，日志保留首部及最后 8192 字节，command.json 记录观察字节、保存字节、限额和截断状态。超限与超时保持失败，不进入成功极曲线。正常返回仍提供原文本解析接口。
- 主流程使用 schema 2 轻量工程包，保存输入、结果、最终几何、表、轨迹、报告和原生文件清单。原生 ZIP 以明确哈希引用分离；打开时显示过程证据未随包验证。缺失引用、与原运行记录或清单不一致的哈希均拒绝。schema 1 旧包及完整 API 保持。
- 新生成的完整原生证据包使用 SHA-256 内容对象，每个独立内容存一次；逻辑路径清单保持。旧原生格式仍可验证。活动工作目录和既有原始运行保留，尚未将所有求解器工作目录改为共享对象；容量治理不等于所有原始过程均已消失。
- 重复保存相同方案内容、当前运行及证据层级时复用已验证存档；包创建时间差异不会再次增加一份存档。不同内容和不同层级分别保留。
- 历史首次整理仅移除 6 份开发验证目录的重复导出。对应本机方案库副本保留；逐文件核对哈希后，实际执行移除→恢复→再次移除，恢复字节一致。用户演示交付、当前基准、失败原始运行均留原位。

6 份历史重复包逻辑字节共 **2,329,996,934 B（2.17 GiB）**。这不是整个项目的净磁盘减少量，新验收包和测试证据另有新增。恢复索引在本机 `local/v031a/history-recovery.json`，执行 `scripts/maintain_v031a_archives.py restore` 可恢复原路径；该工具拒绝目录联接、越界路径和哈希不匹配。恢复依赖所列本机方案库副本，后续维护应将其作为受保护引用。

## 验证与限制

专项测试覆盖正常输出、洪泛、超时、所属进程结束、轻量草案、重复保存、非法分离引用、内容对象去重与危险路径拒绝。任务相关首批 14 项通过，22.95 s；完整回归为 412 通过、14 失败、1 项既有第三方提示，754.60 s。14 项失败均来自旧界面测试按位置点击了本机持久任务面板，未操作目标学科按钮；隔离用户任务历史后，相关 42 项全部通过。随后分级读取接口及受影响归档/任务/比较/界面复验为 **65 项通过、0 失败，120.27 s**。各批次有重叠，不相加为总通过数。

首轮沙箱测试在任务/UI 后续阶段未正常结束，主动停止并保留目录；缺清单时的 KeyError 已改为可理解的 ValueError。常规隔离环境复验正常。完整回归第一次启动与代表产物检查时间重叠，随即停止；正式回归在代表检查完成后另开目录串行运行，首次记录保留。

完整原生证据需要按需取得才能进行逐文件原生审计；轻量包没有把未携带的过程标为已验证。原生 ZIP 已去重，工作目录的逐工况副本与全部历史测试目录尚未迁移。首轮历史清理以明确、可恢复的小范围完成，不扩大到共享运行环境和用户交付材料。

未启动 AVL 多工况、插值模型、离散或收敛提速。整机速度基线仍为 V0.3.1 的 57.75 min；归档变小不能作为计算已加速的证据。专业物理验证状态保持原记录。

本地证据：`local/v031a/representative/validation.json`、`local/v031a/tests02.log`、完整回归日志及历史恢复索引。复现入口：`scripts/validate_v031a.py`（依赖本机已保留的 V0.3.1 代表运行与历史失败输入）。

## 最终读盘与恢复检查

禁止读取 `native_evidence.zip` 的检查发现通用 `get_results` 仍会先校验原生包。已增加显式分级参数：默认完整校验保持，轻量保存/查看跳过原生 ZIP，其他产物仍逐项校验；新增测试确认非原生产物损坏仍被拒绝。最终实际代表轻量包构建通过“禁止原生 ZIP 读取”的探针。首次探针失败日志保留。

真实存档经 AppTest 打开，原生证据分离提示和最终三维网格组件均存在，无界面异常；此项验证组件数据和会话逻辑，不声称完成浏览器视觉检查。去重证据恢复工具实际还原了同内容不同路径的测试文件，并拒绝覆盖已有目标目录。完整 33,578 个逻辑文件的内容哈希已逐一核对。恢复入口为 `scripts/restore_native_evidence.py`。

主流程提供“包含完整原生过程证据（文件较大）”开关，默认关闭。普通方案保持轻量，选择完整层级后仍执行完整原生审计。底层完整 API 与旧包读取保持可用。
