# V0.1.6 需求、任务与总体服务验证

本版完成“从少量需求开始”的产品入口，以及固定 FAST-GA 公开任务的共用服务。需求可保存、导入、确认和展开为任务定义；新飞机自动定尺寸按路线图在 V0.1.7 接入。本版没有将双发参考机的参数当作用户单发方案的设计结果。

## 1. 需求模型和用户入口

版本化 `DesignProject` 内部使用 SI，包含任务载荷、重量要求、任务、假设来源及确认哈希。界面显示 km、h、km/h、min，保存为 m、s、m/s。载荷合计明确包括机组、乘员、行李、任务设备。

| 模式 | 处理 |
|---|---|
| 规定起飞重量 | 保存规定值，后续设计保持其值并验收质量平衡 |
| 重量上限 | 保存约束上限，重量仍需由任务求出 |
| 待求重量 | 数值字段留空，与后续迭代初猜分开 |

航程任务、航时任务、同段双约束、往返加额外留空分别展开。规定航迹距离与最低空中时长不自动叠加；往返填总距离，留空才作为额外时长。储备独立列项，不贡献主任务航程/航时；地面滑行另列。主任务航时不会由航程除以巡航速度伪造。

检查包括：载荷不能达到/超过规定重量或重量上限；规定值缺失、待求量携带规定值、任务字段遗留或缺失均返回冲突。拒绝未知字段、非法模式、非有限数值和无来源假设。输入检查不能判断尚未计算的性能可行性，结果显式为 `not_evaluated`。

确认哈希覆盖需求和假设，序列化/重载及整浮点等价表示保持一致；更改重量、载荷、任务或储备后确认失效。默认首页为“新建飞机方案”，已保存记录与当前编辑值不一致时提示重新保存，保留上次记录。状态区分 `needs_confirmation`、`invalid_input` 与 `requirements_ready`。

正式验证执行 3 种重量模式 × 4 类任务的 **12 组组合**，全部完成输入快照、任务段、摘要和产物完整性核验；这些组合验证任务定义，没有执行 12 架飞机设计。自动化测试的确认来自合成案例脚本，与用户确认记录区分。

## 2. 公开参考输入和真实接口

使用 FAST-OAD-CS23 1.4.0 随包 Beechcraft 76 XML 与 fastga.yml，调用生成配置、生成输入和 `evaluate_problem`。标签提交为 `8092ced91226a3583138ecf0a42d80909aaee346`，上游地址见 [接口说明](FASTGA_INTERFACE.md)。本地 XML、配置和 reserve.py 已与该标签的公开内容比对；归一化换行后内容一致。

参考 XML SHA-256：`fa81a18c904b5fe6925806d0b647ac99c24e68e9e25889c882b980ab6b7ed3ff`。运行前必须匹配；上游文件不修改。沿用已有家具质量导数及 CSV 兼容层，全部第三方版本和锁文件保持原状。

运行后按 OpenMDAO 真实变量来源核对 **20 项标量**的输入/输出角色及 SI 单位。MTOW、载荷和翼面积为求解输出，功率/发动机台数为输入；将 MTOW 写进输入 XML 不会变成规定重量设计。公开任务为双发，2 名乘员之外内含 2 名驾驶员，80 kg/人加 60 kg 行李，载荷为 380 kg。

## 4. 上游限制与导数核查

保留三个已知经验关系范围问题：升降舵弦长比 0.34、平尾/垂尾面积比约 2.624143、有符号起飞升降舵偏角 −20°。运行状态为 `executed_with_limits`，参考回归通过与工程适用性分别显示。

本轮另检查储备公式 `m_r=m_c/t_c×t_r×k`：取 m_c=120 kg、t_c=7200 s、t_r=2700 s、k=1，函数值为 45 kg。独立中心差分与解析关系一致：

| 导数 | 中心差分及正确解析值 | 上游 1.4.0 compute_partials |
|---|---:|---:|
| ∂m_r/∂m_c | 0.375 | 19,440,000 |
| ∂m_r/∂t_c | −0.00625 | 324,000 |
| ∂m_r/∂t_r | 0.016666667 | 864,000 |
| ∂m_r/∂k | 45 | 2,332,800,000 |

确认属于上游解析导数错误，函数值本身正确。当前流程是非线性模型求值，不运行梯度优化，原输入和上游源码均保留。接口明确 `gradient_optimization_supported=false`。后续若采用梯度路径，应先以插件修复并验证，不能仅凭总体回归通过就宣称梯度可靠。

## 5. 测试和交付证据

新增模块首组 **35 项通过**；增加 CLI 覆盖、需求摘要后，首轮全套 **142 项通过，105.715 秒**；发布审阅补齐旧 CLI 别名的自定义输入拦截后，最终全套 **143 项通过，104.223 秒**，仅既有 traitlets 元数据弃用提示。4 项本地原生集成都实跑；公共 CI 按环境跳过它们，云端状态在推送后核验。新增测试覆盖模式/任务语义、确认失效、保存重载、非法输入、守恒账目故障注入、实际导数差分及新首页的成功/失败/受限提示。

正式编排：`scripts/validate_design_entry.py`；原始记录：`local/v016-design-validation`。交付前恢复参考 worker 原有 LF 换行，AST 一致，随后通过共用服务再次复算，以保持最终脚本哈希与记录一致。运行编号、源码/worker/产物哈希及公开结果汇总于 `validation/v0.1.6.json`；推送/CI 证据保存在 `local/v016-release-sync.json`。

本轮没有新增依赖；仅刷新项目 editable 元数据为 0.1.6。原始参考 XML 和完整求解产物留在本地。模型验证属于接口/数值回归与账目检查，独立物理验证仍为 false。V0.1.7 的主任务是单发构型需求绑定、约束定尺寸和重量/燃油/功率迭代；既有结构稳定性风险继续作为后续约束保留。
