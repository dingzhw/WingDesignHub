# V0.3.0 评审后的下一步执行计划

原计划日期：2026-11-17，编制基于 V0.3.0。用户已批准本计划；V0.3.1 的执行结果、验证及剩余项另记于[本版验证](../VALIDATION_V0.3.1.md)，以下保留原工作包和预先规定的验收条件。

依据：[评审回复书](REVIEW_RESPONSE_V0.3.0.md)和[当前路线图](../ROADMAP.md)。原报告、旧运行及校准/验证角色保持不变。任务编号 RV-01～RV-33 沿用回复书，原专业问题 R01～R07 继续保留。

## 1. V0.3.1 要交付什么

**让用户面对的是同一架飞机、同一次计算和可管理的任务。** 下一版首先解决已确认的一致性与可靠性缺陷，并取得后续提速需要的性能基线。

用户应能从现有需求建立任务，看到所用模型和工具是否可用，提交后查看阶段/轮次；切换页面、重连或调整另一方案不会丢失已提交任务。显式取消能结束该任务进程，历史计算可重新选择；参数、几何和报告对应同一个运行。输入不合法时保留草案和历史结果。

本版不加入结构反馈，不校准发动机，不直接改变支柱系数或强行移动 CG，也不放宽 XFOIL/AVL 的适用范围。尾翼跨模块定义冲突属于本版必须修复的工程错误，其结果差异单独验证。前后总体值因此发生变化是合理的，不能强行维持旧结果。

## 2. 开工记录与问题复现

沿用 `docs/PROGRESS.md` 作为开发记录；实现开始时建立一个 `local/v031/` 工作目录，记录源码身份、工具版本、输入、命令、运行 ID、耗时和结果。若目录已经存在则先核查内容并续记，不覆盖历史。

冻结以下基线，不将它们都再次重跑一遍：

| 基线 | 用途 | 使用方式 |
|---|---|---|
| V0.3.0 A/B/C 三方案与 399 项本地回归记录 | 旧结果和软件覆盖基线 | 读保存记录、运行清单和版本；不跨模型变化要求数值完全相同 |
| 方案 A、现有完整比较包 | 结果选择、三维预览、保存/重开与导出开销 | UI 测试复用真实已计算结果；单独统计读/验/包/下载时间 |
| 规定 1100 kg 极曲线失败 | 保留原失败条件，防止修复其他问题时掩盖 | 提取最小工况、原翼型、命令及日志；有上限的独立复现，不运行整条失败链 |
| 1100 kg 上限超限、桨尖 Mach 超限 | 失败/受限结果展示与兼容检查 | 原状态读取；用有针对性的模块测试核对新逻辑 |
| 尾翼冲突 | 当前重量/几何输入不一致 | 冻结总体尺寸和功率，只核对重量组输入、尾翼几何及质量变化 |
| 页面操作时序 | 旧几何显示、父运行切换、输入越界 | 用 AppTest/实际浏览器确认触发路径，记录“隐藏”和“数据删除”的区别 |

首先建立三个明确区分的清单：已确认错误、待实验的原因解释、性能优化候选。`k_vh` 先核对活动组件和调用路径，不添加一个会错误拦截当前 AVL 方案的全局面积比上限。

## 3. 工作包、依赖与交付

### W1：共享构型定义与模型域检查

对应 RV-07/09/10/14。先于原生正式回归完成。

1. 将平尾/垂尾厚度、展弦比等已发现重复定义迁入同一配置或构型契约。既有用户配置有明确迁移规则；以现有可见 NACA0012、垂尾展弦比 1.6 作为兼容模板基线，记录修复前后的重量输入。
2. 为每个实际使用的组件列出输入范围、采用/裁剪/拒绝行为及来源。组件级范围与整机模板范围分开；上游参考任务的域警告单独记录。
3. 在推进启动前检查必要的组合可用域：桨径/转速/速度/高度/弦长与局部 Re/Mach、表覆盖关系。需要 BEM 才能精确确定的局部状态采用保守预检并保留运行期检查，不把预检说成完整气动验证。
4. 标明座舱和发动机包络尚未匹配的组合。缺少物理依据的尺寸不静默改写；只能作为研究输入或返回受限状态。

交付：共享参数字段、迁移/域检查记录、至少一个冻结构型的质量输入对照。测试包括改厚度/展弦比后所有消费端一致；旧记录未被覆盖；活动/未活动经验组件不混淆；参数分别合法但组合越界时有正确诊断。

### W2：持久任务和外部进程所有权

对应 RV-20/28/29。尽量复用当前独立工作进程和运行目录。

1. 内核服务提交任务后返回 job/run ID；CLI、Python 和 UI 使用同一状态语义。状态至少区分排队、运行、取消请求、已取消、失败和已完成；工程结论另列“已检查约束满足/超限/域外”。
2. 单机默认一项原生整机任务运行。记录 PID、创建时间、父子关系和心跳，防止 PID 复用导致误杀；相同提交不得因双击产生两次运行。
3. 前端轮询只读取小型状态/迭代文件，切页或断线不结束任务。重新连接能列出活动与历史任务，明确当前选中的结果。
4. 显式取消/超时/工作进程异常时清理该任务拥有的进程树，保存最后完整检查点及终止原因；未成功退出时显示“取消未完成”，不能先显示已取消。
5. 应用重新打开后核查运行记录与真实进程。失联任务标为已中断并提供日志/新建重算；只有经过验证的恢复边界才提供续算。
6. 工具设置与 `doctor` 补 Julia、项目环境、CCBlade 版本及最小检查。保持隔离环境，不修改系统 PATH 或其他工程配置。

交付：任务状态契约、后台单队列、进度与历史入口、取消/异常清理测试。采用可控的测试子进程先验证生命周期，再做一项真实原生任务的取消/恢复检查；不通过反复启动整机批次验证简单状态逻辑。

### W3：当前结果、输入与最小主流程修复

对应 RV-23～28。

1. 将独立梁“开始计算”改为明确的基准/专项入口；主入口保持“新建飞机方案”。先保留旧功能，不做大规模页面重写。
2. 使用明确的当前运行选择：参数表、预览、报告、归档、比较和模型标签同时切换。初步、气动反馈和推进闭环可以查看历史，不能由某个 session key 的偶然顺序替用户换结果。
3. 输入边界/步长由 schema 与模型范围生成，区分必填要求、工程假设和模型有效域。字段错误就地提示，仍可保存草案和查看旧结果。
4. 补失败码的中文含义和可操作提示；标清未计算项。显示单位转换先在相关页面统一，完整展示规范留 V0.3.5 验收。
5. UI 测试依次覆盖：初步→推进→气动→选回推进；新旧几何切换；保存/清空/重开；错误输入后恢复；缺失 Julia/CCBlade；失败结果重开；正在运行时切页/重连。

交付：主页面与方案卡正确关联、历史入口、输入/失败回归。展示和逻辑检查使用真实冻结结果，不伪造新的工程求解成功。

### W4：性能与数据开销基线

对应 RV-03/16～22/30/31。只测量和定位，本版不混入未经验证的降阶模型。

记录环境、CPU/内存、并发数、源码/模型身份、输入与缓存状态。对以下阶段单独计时和计数：OpenVSP 建模/相交/遮蔽，AVL 启动/计算/解析，XFOIL 查询/命中/实际求解，CCBlade，重量/任务积分，哈希、复制、打包、读包、校验和界面下载。

先用一个冻结外形、一个有限任务子集和已有归档测量热点；修复稳定后，用一架正式代表运行记录总体时间和资源。复用计时结果为 V0.3.2 选择方案，不为确认数量而重新跑三套完整历史批次。涉及完整回归、原生整机及其他原生负例时仍串行。

性能台账必须把冷缓存、温缓存、离线表生成与最终原生审计拆开。文件统计以内容哈希区分副本与不同迭代。浏览器下载等待与服务端打包/内存事件分开测量，不能直接互相归因。

### W5：验收和发布准备

完成 W1～W4 相关修改后冻结源码；再运行必要回归和正式原生代表任务。若验证期间修改影响计算的代码，应明确哪些结果失效并重验，不能混用前后源码通过数。

输出 `VALIDATION_V0.3.1.md`、机器可读验证摘要、已关闭/未关闭 RV 清单、模型适用域和使用说明。更新 PROGRESS 与 ROADMAP 的完成状态。软件版本仅在本版通过条件满足后推进。Git 提交/推送按当次授权和明确文件清单执行，未授权不夹带当前其他文档、演示或输出目录。

## 6. 后续两类验证必须分开

### V0.3.2：同一物理模型的快速实现

先保留 V0.3.1 修正后的原生模型为基准，再选择原生多工况、导数复用、有界极曲线、模板面积和内外层更新。性能目标和数值误差约束在原生验证前写入配置；每项优化分别比较后再联算。

- **数值验收拟定预算**：非节点总 CD 相对差≤2%（沿用既有门槛）；任务燃油/安装功率相对差≤1%；起飞质量相对差≤0.5%；近零量明确绝对容差。最终原生配平残差继续采用既有 1e-5，整体账目闭合与最终收敛门槛保持。误差对约束状态有影响的案例必须原生核查或标为待复核。
- **性能阶段门槛**：同机、同输入、相同缓存条件下，三方案核心计算实测加速至少 5 倍；目标是已建表模板三方案≤3 min。冷建表和原生审计时间单列。达不到 3 min 就保留性能受限状态，不将预测幅度写成成果。
- **归档预算**：核心输入/结果/诊断/manifest 目标<5 MiB；含必要图谱、最终 CAD 和报告的可移植工程包初始预算≤20 MiB；全量调试证据另导出，实际大小据实记录。两种口径不混用，超过预算必须解释主要构成，不偷偷排除重开所需数据。
- **资源和可靠性**：默认单整机任务；内存峰值、提交余量和外部进程数入报告。小改 UI 不反复哈希/打包大档案；模型/Julia/数据变化仍触发正确失效。

一次限定的失败极曲线专项调查最多安排 2 个工作日的首轮实验；未关闭则给出已验证域和缺点掩码，回到主流程。有界快速路径无法满足误差预算时保留原生模式，不把近似结果标为已验收，也不继续无限扩充极曲线网格。

### V0.3.3：主要物理假设与数据基准

先确定具体飞机、数据条件和可取得资料，再冻结校准/检查分工。顺序为：参数/质量口径 → 部件与乘员站位 → 支柱及安装影响 → 速度安排影响 → 发动机/桨/油耗 → 固定构型误差 → 需求驱动重定尺寸。每次只改变有归属的一组假设，保留交互影响。

首选现有 Piper VB-760 对应的 PA-28-181 Archer II。开工先核对手册修订、对应发动机/桨/轮罩、固定几何及空重口径，再决定它能承担哪些对照。65% 耗油校准点、55%/75% 同源留出和条件不匹配的 Lycoming 对照沿用 [FUEL_MODEL](../FUEL_MODEL.md) 的既定角色；未取得新的独立资料前不改名为独立验证。首轮资料核查限 2 个工作日，形成可用/缺失字段表；缺项转为专项数据任务，继续完成有依据的对照。

最低交付是一架具体单发固定构型基准的条件表、可比较输出与剩余缺口，不预先保证全部指标“验证通过”。独立飞机、全尺寸推进数据不足时保留研究适用域和敏感性；若它们左右方案结论则禁止给唯一推荐。V0.3.4 在这些明确边界内接主要约束，V0.3.5 仅做主流程收口及试用，不新增大规模通用重构。

## 7. 何时回到结构主线

V0.3.6 的正式本机结构算例需要：共享几何/部件质量和 CG 定义一致；已检查配平状态及未覆盖力矩明确；任务/载荷状态与限制/极限系数定义清楚；快速计算和原生校核能正常完成；主流程可保存重开并解释结果。需要的材料、两梁翼盒、肋距、燃油/设备分布、支承由相应专业确认或作为明确研究假设。

**不要求先完成第二架整机独立验证、全部安装干扰、全部历史报告迁移或全部工具公共 CI。** 这些未关闭项按影响范围保留。低速性能/稳定性域不够支持的载荷状态则不能借“结构研究”跳过，应使用有来源的规定载荷并明确其角色。进入结构后坚持本机载荷→快速定尺寸→机翼质量单次替换→总体反馈；有限元只检查代表工况。
