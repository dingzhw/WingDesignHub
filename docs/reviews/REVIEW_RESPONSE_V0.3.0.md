# WingDesignHub V0.3.0 评审意见回复书

日期：2026-11-17。审阅对象：[原评审报告](REVIEW_REPORT_V0.3.0.md)，软件基线 `f8fc6bccd83e1a5a3a614320cd70c0d5a5f6103e`。

本次工作为评审核查、意见回复和计划调整，未修改计算内核、未重跑整机求解、未发布新软件版本。原评审报告保持原样。以下“接受”“修正后接受”表示处置决定；问题关闭须有后续版本的实测证据。本回复也不代替总体、气动、推进、结构专业人员的签署。

## 一、总体回复与优先顺序

**接受报告的核心判断：项目目标没有改变，确定性计算链已经贯通，但模型建设的轻重缓急、计算成本和面向用户的流程需要调整。现在直接沿原 V0.3.1～V0.3.3 加入结构反馈，会把已有构型偏差、操作问题和计算负担继续放大。**

应优先处理六件事：

1. **保证同一架飞机在各模块中的定义一致。** 尾翼厚度、垂尾展弦比确有冲突；部件站位过于粗略，几何、动力与适用范围尚未形成一致的约束。
2. **识别决定结果的主要假设。** 支柱阻力、重心布局、爬升速度安排、发动机重量/耗油和螺旋桨安装影响，比继续提高局部离散精度更值得优先核查。
3. **让长任务可管理、结果可找回。** 修复错误结果关联和输入越界交互，提供任务编号、进度、取消和重连；先解决可靠性，再承接更多学科。
4. **降低重复计算和归档成本。** 原生求解保留为基准与关键点校核，引入有明确适用域和误差检查的快速查询。保持可追溯性，但不把每个中间文件都装入日常方案包。
5. **补齐影响定尺寸的主要约束。** 起降距离、增升装置、合理速度安排、装载重心包线和尾翼约束，前移到结构闭环之前的总体模型完善阶段。
6. **补目标机型的物理对照。** 先冻结一架资料较完整的常规单发金属飞机作为固定构型基准，再检验需求驱动定尺寸。上游回归和数值收敛继续保留，不能充当整机精度依据。

同时，需要修正报告中的一些表述。当前结果与同类飞机存在差异，足以触发核查，但尚不足以把全部偏差归因于某一个模型；某些改善办法也不能直接作为已证明正确的实现。下面逐项说明。

新的执行顺序为：**V0.3.1 一致性与任务可靠性 → V0.3.2 有界快速计算与轻量归档 → V0.3.3 构型/主要假设及单发基准 → V0.3.4 一级定尺寸约束 → V0.3.5 总体使用流程验收 → V0.3.6～V0.3.8 本机载荷、翼盒定尺寸及结构反馈 → V0.4.0 阶段验收。**

节点编号与验收以[更新后的路线图](../ROADMAP.md)为准；V0.3.1 的具体工作包、测试和停止条件见[下一步执行计划](NEXT_PLAN_V0.3.1.md)。这次调整设置有限的前置节点，不以完善所有气动、推进或软件架构问题作为启动结构工作的条件。

## 三、方向与航空模型意见回复

### RV-01：早期结构工具与总体主流程分离

**接受产品入口和连接关系方面的意见；不把既有结构验证判为无效开发。** 当前总体确实仍用经验结构重量，代表梁、矩形半翼、平板及 OAS 官方算例是独立验证任务。CRM/uCRM 算例用于确认上游接口，其构型和工况不应出现在用户的单发飞机结果中。

V0.3.1 先消除“开始计算”指向独立梁算例的歧义；V0.3.5 将这些功能归入“方法验证与基准算例/专项分析”。V0.3.6～V0.3.8 复用其中已验证的载荷映射、梁壳对照和板稳定性方法，接入本机几何、载荷及质量替换。关闭依据是依赖关系和运行证据，不以删去多少文件或降低多少代码占比衡量。

### RV-02：起降、增升、重心与尾翼一级约束缺失

**接受，调整为结构反馈前的明确交付。** 当前 `sizing_physics.geometry()` 的翼面积约束主要为失速、巡航升力和携油体积；功率约束及配平已有接入，但起降场长、装载 CG 包线、尾翼控制约束未完整进入定尺寸。

V0.3.3 建立一致的部件/乘员/燃油站位与机翼、尾翼布置参数；V0.3.4 接入起飞滑跑和越障、着陆、海平面与巡航高度爬升、概念级襟翼和纵向尾翼约束。先声明跑道状态、风、温度、高度、障碍高度及发动机/螺旋桨近静态数据范围。**起降距离目前是未计算，不能记成距离为零或约束自动满足。**

规则版本和飞机类别必须进入条件。CS-23 的现行条文、符合性方法与历史规定并非同一个输入集；“15 m / 50 ft”采用哪种数值应显式记录，不把 15 m 与 15.24 m 在程序中混用。后续按选定的公开条款建立概念估算，不在本阶段宣称适航符合性。[EASA CS-23 官方规则](https://www.easa.europa.eu/en/document-library/easy-access-rules/online-publications/easy-access-rules-normal-category-CS-6-AMC-GM-5?erules-id=ERULES-1963177438-6992)

### RV-03：数值精细程度、物理可信度与计算成本失衡

**接受。** 约 160 min 的三方案增强运行不适合日常交互筛选。表面上更精细的数值模型，也不会自动消除支柱、站位、发动机图谱等输入和方法误差。

改进为“快速方案探索＋原生关键点复核”，并同时列出数值误差、模型未覆盖项、假设敏感性与实际验证状态。界面默认精度按工程阅读设置，保留全精度审计数据。报告中的六项评分属于评审判断，没有可复现的评分量表，不作为验收分数；“物理精度已很高”或“已偏离真实规律”的定量断言均须落实到具体基准和条件。

### RV-04：支柱阻力是当前重要不确定项

**接受优先核查；不直接把 1.2 替换为 0.12～0.30。** V0.2.4 的特定阻力点支柱占比约 31.12%，V0.2.5 固定构型敏感性显示显著任务油量变化，证据支持其优先级。这些比例属于对应版本、构型与工况，不能直接当成 V0.3.0 全航程的统一占比。

V0.3.3 将支柱、轮胎、轮罩、整流包覆和接合部拆开，核对外形、暴露长度、迎风/湿面积定义及速度方向。圆柱横流系数与流线构件系数若参考面积不同，直接替换会引入新错误。先固定几何做分项阻力对照和高/低假设，再做重定尺寸；所用经验图表需给出原出处、几何与 Re 条件。没有确切包覆结构资料时保留裸露/整流两种情景，不以符合预期油量为选值理由。

### RV-05：`CL≤0.50` 速度安排限制了爬升设计

**接受问题，修正实施方式。** `FeedbackOptions.schedule_cl_ceiling` 默认 0.50，`feedback_schedule()` 以此提高爬升/留空速度下限。这是当前方法域限制，不是最佳爬升速度、经济速度或飞机物理极限。

V0.3.3 先分别量化固定飞机下的速度安排影响和发动机重定尺寸影响；V0.3.4 在受验证的升力、配平和推进范围内搜索爬升/留空速度，并把用户性能要求与求解器适用域分开。不能仅将 CL 改为 0.75～0.90、迎角改到 8°来消除功率超限；还要核查翼尾局部升力、失速裕度、舵量、推力与耗油图覆盖。

原先约 45.5 m/s 也是 `speed_schedule()` 的 1.3 倍净构型失速速度规则，并非已求解的最佳爬升速度。报告的 V³ 比较能解释固定 CD 条件下寄生功率的速度敏感性，但不能直接证明总需用轴功率或发动机质量应下降同样比例。完整变化还包含诱导阻力、爬升功率和推进效率。

### RV-06：粗略部件站位导致前重心及较大平尾负载

**接受，列为构型核查重点。** 当前 `sizing.cg_ledger()` 把机体、动力、系统、设备等大类放在固定机身比例站位，全部载荷和燃油又集中到翼四分之一弦位置。保存结果确认方案 A 起飞 CG 为 5.17% MAC，说明站位假设足以影响配平和后续载荷。

V0.3.3 建立翼、身、尾、发动机/桨、设备、前后排乘员、行李及油箱的分项台账。由布局生成 CG，记录满油、任务末、前后装载等组合，并检查机翼位置、平尾安装角与舵量。**不把“CG 必须等于 20%～30% MAC”作为回填条件。** 该区间可以辅助对照，但本机允许 CG 范围须由稳定性、控制能力和布局共同确定。缺失部件站位用可见区间，不隐含压舱物。

较大负舵偏与某次 XFOIL 失败之间存在关联，尚不能据此确定单一因果；详细处置见 RV-13。

### RV-07：重量模型与几何模型的尾翼参数不一致

**完全接受，V0.3.1 优先修复。** [重量输入](../../src/wingdesignhub/fastga_mass.py)的平/垂尾厚弦比 0.10、垂尾展弦比 1.8，与[几何契约](../../src/wingdesignhub/aircraft_geometry.py)的 0.12、1.6 不同。它会造成同一方案实际使用两套尾翼定义，是明确的工程一致性缺陷。

将这些参数收敛到统一配置/构型契约，由质量、几何、气动共同消费。先用现有可见 NACA0012/垂尾 1.6 模板作为兼容基线，并记录选择；以后允许有来源的修改。冻结其余输入，分别记录质量组输入、部件质量和后续总体变化。旧结果保留原版本；修复后生成新记录，不能直接修改旧结果使其看似一致。

### RV-08：FAST-GA 单发空重与发动机安装质量缺少目标验证

**接受验证缺口；暂不接受“788.4 kg 或 209.4 kg 已证明错误”的结论。** 同类飞机空重值得对照，但须统一 basic empty/operating empty、不可用油、机油、发动机裸机/安装质量、航电和选装设备口径。当前类别名与具体部件还需核对，尤其是系统重量约 197.2 kg 的组成和经验式贡献。

V0.3.3 先做固定几何、固定额定功率的重量分项对照，查出主导差异；再分析自由定尺寸的反馈。需要追溯的包括发动机缩放律、系统/设备的常数项、座位与载荷定义、最大燃油与载荷输入。没有部件实测数据的项保留估算区间，不用一个总空重系数掩盖多项定义问题。

### RV-09：面积比越界是否已经触发 `k_vh` 静默截断

**接受适用域管理要求，修正当前调用链判断。** 本地上游 `figure_digitization.k_vh()` 确实在表外使用 `np.clip`，并发出告警；表上限约 1.97508，方案 A 面积比约 2.38194。可是它的调用位于 `aerodynamics/components/vt/compute_cl_alpha_vt.py`。当前 `FastGAMassModel` 只组装 `MassBreakdown`，增强气动与配平采用 AVL。所查调用链不支持“此面积比已在当前重量—AVL 闭环静默裁剪”的断言。

V0.3.1 对**实际调用的组件**建立适用域/裁剪记录，并保留公开 FAST-GA 参考任务原有告警。以后若使用该垂尾经验组件，须先检查范围或选择有依据的替代方法；不能只为了落入 `k_vh` 表域而改变当前飞机尾翼面积。域检查要说明组件是否被使用，避免把未调用模型的告警当成当前飞机错误。

### RV-10：固定几何模板覆盖范围过宽，安装角等不可调

**接受。** 主翼 NACA2412、尾翼 NACA0012、零安装角/扭转/上反角，以及固定座舱截面和 1.9 m 桨径，均在当前源码中确认。允许填写 2～6 座或 40～400 kW，并不等于该外形模板在整个输入范围内已经验证。

V0.3.1 先显示模板范围、核查组合可用域，避免几何、推进接口各自通过而整机组合失效；V0.3.3 将关键布局和安装角提升为配置参数。桨径须与地面间隙、发动机工况、叶素 Re/Mach 和尺寸包络共同检查。报告所列“典型”安装角可作为敏感性候选，不能无依据统一写入全部机型。

### RV-11：机身与动力力矩、滑流缺项影响配平和稳定性

**接受。** 当前纵向计算是升力面配平；报告中的“中性点普遍前移 5%～12% MAC”缺少与本机匹配的证据，不能作为固定修正值。

V0.3.3 给出机身力矩、推力线偏置及动力影响的有来源初步估算或敏感性区间；V0.3.4 的 CG/尾翼约束必须显式携带这些覆盖情况。超出该范围时返回“需专项校核”，不输出完整操稳包线通过。完整动力干扰图谱可后续开展，毋须先上全机 CFD。AVL 自身有细长体功能，但官方也要求谨慎使用机身模型，接入仍需对照。[MIT AVL 3.40 文档](https://web.mit.edu/drela/Public/web/avl/avl_doc.txt)

### RV-12：实际翼型与转捩条件缺少匹配试验对照

**接受；修正“trip=1 就是全翼型层流”的理解。** 当前翼尾确为 NACA2412/0012，E387 检查不能证明这些翼型在本机 Re、Mach、铰链和舵偏下的误差。XFOIL 的 `trip=1` 允许按 e^n 条件先发生自然转捩，并非保证层流一直保持到尾缘。[MIT XFOIL 转捩说明](https://web.mit.edu/drela/Public/web/xfoil/xfoil_doc.txt)

V0.3.3 从清洁 2412/0012 开始，按试验 Re、Mach、表面粗糙度/转捩、二维修正和读图误差建数据表；带舵翼型另找匹配铰链、舵弦比、缝隙与偏角资料。NACA TR-824 是合理来源入口，但其覆盖四位数翼型，不等于现成提供当前 0.7c 铰链、所有舵偏和条件的独立对照。[NACA TR-824](https://ntrs.nasa.gov/api/citations/19930090976/downloads/19930090976.pdf)

自然转捩、较早强制转捩及粗糙度情景用于评估结果敏感性。报告所述总阻力增加 11.2% 应保留具体输入与计算记录后再采用，不作为全机通用修正量。

### RV-13：规定 1100 kg 方案的平尾极曲线失败

**接受必须处理的缺口；失败机理仍待验证。** 既有记录确认 Re≈236.8 万、Mach≈0.17626、舵偏≈−7.99°时发生 `TRCHEK2/N2` 异常、NaN 和超时。当前完整预算验证被中断；错误状态保留下来了，并不等于该方案已验证不可行。

V0.3.1 保留可重复的最小工况和邻域清单；V0.3.2 开展有限的翼型几何、面元分布、初始解/连续推进和 Re/Mach/舵偏邻域检查，读取实际变形翼型、压力和边界层结果后判断原因。修改 CG、舵偏或任务条件得到的新成功算例，不能作为原工况数值问题已经修复的证据。调查按限定工作包执行，若没有可靠解则保留缺点和域外诊断；不填零、不跨洞插值、不无限延长超时。

### RV-14：小桨验证、全尺寸桨效率与输入组合域

**接受验证层级和组合域方面的意见。** 官方 APC 10×5 的 17 点检查是该小桨和接口的证据；不能直接移用于 1.9 m 三叶合成桨。约 85% 的计算效率与真实装机效率之间有安装和试验条件差异，报告提出的“必然高 5%～10%”目前缺少对应全尺寸数据。

V0.3.1 在调用前检查桨径、转速、速度、高度和弦长组合对应的局部 Re/Mach 与现有表域；不能将单参数允许范围误作组合可用范围。V0.3.3 补候选全尺寸桨资料及安装损失情景；效率、推力、轴功率、螺旋桨自身损失和机体滑流阻力的归属分别记账。缺失目标试验时结果仍是合成桨方法研究，不给定未经核实的统一效率折扣。

### RV-15：通用发动机耗油图替换后的显著油量变化

**接受优先核查；不把旧单点校准值直接强加给新图谱。** 从约 109.4 kg 到 82.6 kg 的对比包含模型替换与重新定尺寸，不能将全部差值归于耗油图缩放。原 Piper 校准对应特定型号、混合比和功率段，通用发动机图的数值回归也不证明具体 Lycoming/Continental 发动机的实测精度。

V0.3.3 按三组对照分解：①固定飞机、任务速度和推进效率，只换耗油；②固定飞机与任务，换完整发动机/桨模型；③用同一需求重新定尺寸。逐段记录富油/经济混合比、额定与连续功率、转速/扭矩、高度修正、低负荷/地面估算及其油量占比。核查通用缩放式的来源与范围，具体发动机数据足够后才校准；连续功率模型与离散商品选型分别输出。

## 四、计算效率、任务和归档意见回复

### RV-16：用少量 AVL 状态代替重复牛顿配平

**接受降阶方向；不把“每轮恰好 3 次 AVL”作为普遍成立的算法。** 当前每个任务点重新启动配平，并重复写读详细涡元，改进空间明确。固定几何、小扰动、固定 Mach 和控制定义时，线性升力/俯仰矩关系可以复用；质量和密度进入目标升力，CG 变化通过一致的力矩平移处理。

但两个自变量的完整二次诱导阻力模型通常包含六个系数，三组一般状态不足以唯一确定它；除非另有经验证的物理约束或涡量基底，不能声称三点同时建立任意配平矩阵和阻力曲面。Mach、舵面几何处理、尾翼状态或非线性项改变时也要检查是否可复用。V0.3.2 比较 AVL 原生多工况/约束配平、导数矩阵和有限采样代理，选择实测可靠的最简单方法；保留独立非节点、边界点及最终状态原生复算。详细涡元按载荷任务和审计需要生成，不能在后续结构需要时丢失载荷信息。

### RV-17：离线极曲线、缓存命中与浮点查询键

**接受标准表和统一缓存；不采用未经定义的浮点四舍五入复用。** 当前精确键保护了工况一致性，其代价是相近状态难以复用。应新增有版本的 `(翼型、Re、Mach、舵偏、cl、转捩、铰链)` 查询表，明确节点、插值误差、有效单元和缺点掩码；原生精确缓存继续负责完全相同的计算。

V0.3.2 统一缓存服务，按实际任务和已冻结模板生成必要数据；记录冷启动建表成本、温缓存查询成本和缓存失效规则。表内独立点直接求解验证，边界外和缺点附近拒绝插值或明确请求补算。**离线建表把求解失败提前发现，不会消除发散或物理模型边界。** 随包分发数据须核对来源、许可、体积和版本；用户自定义翼型不默认为模板库已覆盖。

报告给出的调用/命中数量可作为优化线索，本次没有重做逐次缓存统计；V0.3.1 的计时台账会补按翼型、工况、命中原因分解的基线。仅“未飞留空段”不一定意味着对应点无用：要检查它是否仍被当前功率约束或储备策略引用，再删除未消费分支。

### RV-18：每轮 OpenVSP 与遮蔽采样代价过高

**接受。** `NativeFeedbackGeometry` 每轮生成原生几何，首个阻力点准备面积，其后复用；还会向各点复制同轮 `.vsp3`。固定简单模板可使用解析或几何契约层的面积计算，再由 OpenVSP 核验。

V0.3.2 在已声明的模板范围内验证暴露面积、湿面积与原生相交结果，按误差和布局变化触发重建。最终 CAD、气动和报告绑定同一个收敛方案。安装角、机翼位置、交叠关系或自定义外形改变时不能默认解析公式仍有效。因此“最终只运行一次 OpenVSP”是限定配置下的优化目标，不是所有方案的硬规则。

### RV-19：外层迭代次数、松弛和收敛阈值

**接受减少昂贵重算；不以经验模型误差大为理由放松质量/功率守恒。** V0.3.0 的连续三轮 1e-4 状态变化是数值要求，模型的物理误差是另一件事；FAST-GA 空重“标准差 8%～10%”在本报告中缺少可直接采用的验证数据。

V0.3.2 先分离快速内迭代、几何/表更新及原生最终复核，再测试有界加速、上一点初值和信赖范围。新方法必须保留质量、燃油、功率、CG 残差和约束余量；最终状态复核失败就明确未通过或继续受控求解。Aitken/信赖域为候选实现，不预定必须 3～4 轮收敛。近约束边界时应使用实际误差预算判定“需复核”，不能由近似误差把不可行判成可行。

### RV-20：后台任务、取消与子进程生命周期

**接受，列为 V0.3.1 的使用可靠性核心。** `adapters.execute()` 只在超时时终止子进程树，缺少一般异常退出的完整管理；UI 目前同步等待，缺少明确的任务恢复入口。

需要修正的是“任意切页都会立即抛异常并遗留进程”的确定性描述：当前 Streamlit 运行控制通常在发送界面消息的让出点处理，阻塞 `communicate()` 期间不一定立即执行。WinError 1455 的已有记录说明并发与提交内存风险，不能据此单独证明是页面切换产生的孤儿进程。应通过取消、切页、断线和工作进程异常测试建立因果证据。

采用本地持久任务记录＋单工作进程调度，暂不引入分布式任务系统。前端断开或切换页面不自动取消已经提交的任务；**显式取消由任务管理者终止其拥有的进程树**，记录终止结果。工作进程异常、超时和宿主退出要有清理策略；不误杀其他工程的 Julia/AVL 进程。提供运行编号、当前阶段/轮次、残差、已用时和历史结果。只有形成可靠耗时样本后才显示预计剩余时间；没有检查点语义的中断任务只能重开记录并新建重算，不能伪称断点续算。

### RV-21：中间文件重复、日常方案包过大

**接受，修正重复数量的解释。** 本次读取方案 A 原生清单确认：244 份 `.vsp3` 中有 14 个不同内容，反映不同外迭代；920 份涡元文件也并非全部相同。应按内容哈希去重、保存逻辑路径与依赖关系，而不是按文件名认定重复。

V0.3.2 定义两种导出：日常 `.wdh` 包含输入/假设、模型/数据身份、结果、诊断、报告、必要图谱和最终几何；调试证据包按需包含全部原始过程。共享内容只存一份，读取时校验 manifest 和资源。旧包继续可读，导入只读检查，不执行包中代码。未下载全量日志不影响查看日常方案；依赖资源缺失则明确诊断，不悄悄使用本机其他版本。

不删除历史原始运行以“实现瘦身”。轻量归档不能只保存一串本机路径；跨机器重开、版本与失败状态保留、篡改拒绝都须验收。

### RV-22：打包、校验、下载内存与卡顿根因

**接受重复处理与内存风险；根因结论需保留。** 当前 `build_bundle()` 后立即 `read_bundle()`，`save_bundle()` 又读包，存在可以避免的重复校验；大字节流交给下载控件也会占用内存。但 `project_ui` 已有缓存，报告所述 2701 s 浏览器下载调用等待缺少同时间的服务端内存/CPU/事件跟踪，尚不能认定全部由 1.5～2 GiB 内存尖峰造成。官方说明也确认直接传入下载数据会驻留内存。[Streamlit 下载控件说明](https://docs.streamlit.io/develop/api-reference/widgets/st.download_button)

V0.3.1 记录导出耗时、内存和阶段；V0.3.2 采用按用户动作生成、后台/磁盘产物、可复用的已校验身份及流式校验，避免反复完整展开。导入外部包、内容有变化、已有校验身份不可信时必须重新检查。可执行文件哈希采用运行期缓存，绑定文件身份、大小、时间和运行启动校验，不能只按路径永久缓存。

## 五、界面、报告与软件工程意见回复

### RV-23：入口混杂、主页面步骤和按钮过多

**接受。** 将主工作流组织为“需求与假设 → 总体计算 → 三方案比较 → 报告与归档”；专项分析、方法验证和工具设置分组。初步估算与增强计算保留明确模型名称和验证状态，用户无需依次点击每个求解器按钮。

V0.3.1 先消除误导性入口并给出当前运行入口；V0.3.5 完成流程整合、一键载入示例和用户试用。旧 JSON 属于不同算例类型，可保留导入，但明确格式和用途；不要求所有科研算例硬塞成同一种飞机方案格式。

### RV-24：闭环后显示旧几何、切换种子隐藏已有结果

**接受，V0.3.1 修复。** `sizing_ui.results()` 仍把初步总体记录传给 `geometry_ui.render()`；`coupled_ui.render()` 以当前父运行匹配已有结果，气动反馈产生新父运行后可能隐藏之前的推进结果。磁盘记录并没有因此被删除，问题在于界面选择与依赖关系。

增加显式“当前查看的方案/运行”，参数表、三维预览、约束、比较卡和报告都从该运行读取。历史结果按依赖链列出，输入改变时标为历史或需重算，不丢失入口。用已保存真实结果做先推进/后气动、切页、重开及选回历史的测试，不必反复重跑 50 min 的求解来测界面。

### RV-25：输入边界、单位换算和错误后的页面状态

**接受。** 13 个构型假设输入缺少合适的上下限/步长，外层异常处理会跳过后续渲染。V0.3.1 由同一配置 schema 提供输入限制与中文提示，字段错误不影响保存草案或查看历史；越界不得静默裁剪。CD0 两次增加到 0.052 的案例纳入回归。

V0.3.5 统一显示单位选择，内部仍用 SI；功率可同时给 kW 与机械 hp，不能混用公制 PS。速度换算统一，CG 同时显示米和 %MAC；燃油体积仅在密度、燃油类型和温度假设明确时换算。重量用 kg、载荷力用 N，翼载/功率载荷图轴名标清采用质量还是重量。

### RV-26：英文状态、代码键名、原始 JSON 和精度展示

**接受。** `STATUS` 未覆盖 `polar_failed` 等状态；直接显示字典和源码哈希使正常使用变难。V0.3.1 优先覆盖失败状态，提示问题发生位置、条件及下一步可做的操作；未知状态仍显示原代码辅助定位，不丢诊断。

V0.3.5 完成主流程中文字段、图例与合理小数位，原始键名和哈希放入审计信息。保留开发导出，不以删除底层数据实现“汉化”。计算输出的位数与可相信的工程精度分别管理；没有统计样本时只能展示假设情景区间，不把敏感性带称作置信区间。

### RV-27：HTML 报告、图表与文档链接

**接受。** 以 `<pre>` 包裹 Markdown、靠字符串替换拼接报告，不适合正式技术交流。V0.3.2 的轻量导出先建立统一报告数据契约；V0.3.5 优先迁移总体、增强比较、方案卡及用户会用到的学科报告，其他验证报告按需迁移，不把一次重写全部八类报告作为前置条件。

复用已安装的模板工具，做到中文标题、单位、缺项、状态、假设和结果来源一致；正文给结论与主要约束，审计附录保留技术细节。逐步提供真实计算驱动的约束定尺寸图、任务剖面、CG/MAC 布局和阻力分项图。机翼/平尾展向 y 与垂尾高度 z 分图或明确分面，不能把不同坐标合并为同一连续轴。起降约束还未算出时不绘制貌似有效的起降限制线。文档采用受控的本地阅读/下载入口或已验证网址，修复 Streamlit 页面中的相对链接。

### RV-28：Julia/CCBlade 配置缺失及部署门槛

**接受，V0.3.1 补齐。** 界面与 `doctor` 当前没有完整覆盖推进依赖，而实际调用依赖 `local/propulsion-tools.json`。应提供路径选择、版本/包状态、最小可用性检查和缺失修复提示，区分“找到文件”“能导入”“算例通过”。环境不就绪时不能让用户等待到长计算中途才失败。

锁定版本有复现和二进制 ABI 原因，并非全应取消。后续整理最小安装、总体增强、结构验证等能力配置；OpenVSP Python ABI 不兼容时用明确进程接口隔离。默认不改共享环境、不自动下载任意二进制；安装按项目授权与可信来源执行。

### RV-29：平铺模块、重复服务和密集分号代码

**接受维护性问题，采用渐进改造。** 主流程领域函数不应藏在 UI 中，特别是验证脚本反向导入 `comparison_ui.variants`。V0.3.1 将任务状态、输入验证等相关领域逻辑移出界面；V0.3.2 在新服务中提取运行上下文、产物和错误处理的公共部分，减少两套反馈调度的重复。

不安排一次重排全部 98 文件或凭主观的“75% 重复率”删代码。按所修改的模块补清晰命名、独立语句与函数职责，保留兼容入口。验收看重复行为是否一致、领域层能否脱离 Streamlit 使用、原有记录是否仍能读取，而不是目录数量。

### RV-30：全仓源码门禁与 Julia 脚本身份

**接受粗粒度失效问题，修正“Julia 完全漏记”。** `geometry_service.source_hashes()` 遍历全部 `.py`，造成无关 UI 改动也阻断计算依赖；`ccblade_adapter` 已另外保存 `.jl` 及运行环境哈希，但尚未形成统一的依赖身份规则。

V0.3.2 建立按计算依赖闭包生成的身份：契约版本、核心源码（包括 Python/Julia）、求解器版本/二进制、模型表/翼型、选项及相关上游身份。**仅增加一个人工维护的版本号不足以替代哈希校验。** 增加“改 UI 不失效”“改公式/Julia/翼型/数据必失效”的测试。旧记录保持可读，只在不满足当前计算兼容契约时阻止下游复用；不能为提高命中率删除身份校验。

### RV-31：依赖、私有 API 与原生 CI 缺口

**接受风险，分步处理。** 当前公开 CI 的原生跳过应继续显式列出，367 通过/32 跳过不等于完整增强流程云端验证。硬编码工具路径改为统一配置；优先保留小规模、许可清楚的原生 smoke 测试，正式发布仍对冻结源码执行本地原生矩阵。

“项目没有直接 import”不等于包可从锁文件删除；AeroSandbox、CasADi、Jupyter 等应先查 FAST-GA/FAST-OAD 的传递依赖和所需能力。V0.3.2 审计后按能力拆分环境，独立兼容性测试通过才修改锁定。私有 API 包装集中管理，覆盖当前支持版本，避免扩散补丁。公开 CI 引入二进制须核对许可、来源和完整性；专用 runner、全部工具云端测试与广泛跨版本支持留后续部署阶段，不阻塞当前核心修复。

### RV-32：加筋翼盒快速定尺寸及代表件有限元

**接受结构路线。** V0.3.6～V0.3.8 对同一梯形翼定义载荷、两梁翼盒、蒙皮/腹板/缘条、肋距及必要加筋，进行强度、变形和局部稳定性定尺寸；结构质量只替换原机翼经验质量一次，其他部件继续原方法。CalculiX/OAS 服务于代表状态交叉检查，不在每轮默认启动全壳网格。

既有无加筋代表件的约 14.27 局部屈曲指标是其模型和工况的结果，不应称为“虚假屈曲”，也不应移作本机失败结论。NACA TN-3781 可支持平板屈曲系数选取，加筋板还需相应的压溃、柱失稳与连接假设；TN-3785 的主题即加筋平板压缩强度。首版翼盒据实际选用方法记录边界，不承诺完整结构计算必为毫秒级。[TN-3781](https://ntrs.nasa.gov/search.jsp?R=19930084505)、[TN-3785](https://ntrs.nasa.gov/archive/nasa/casi.ntrs.nasa.gov/19930084529.pdf)

### RV-33：物理验证不足与验证准入规则

**接受，并采用逐级准入。** 上游案例、守恒与数值离散检查是必要基础；物理验证不足的模型可以在显式研究模式下参与概念估算，但需要可见适用域、假设及结果敏感性，不能作为已验证的真实飞机参数推荐。

V0.3.3 首先选定一架资料最完整的具体型号/年份/发动机/螺旋桨/起落架构型，冻结质量口径、飞行条件及手册版本。固定构型对照检验模型；按需求反算尺寸检验设计流程，两者分开。数据在使用前登记校准、同源留出、异条件参考或独立检查，误差标准在运行前冻结。第二架独立型号是后续扩展目标，资料不足时不拼接不同型号/最大性能数据来凑“端到端通过”。

首选已有资料基础的 PA-28-181 Archer II，先核对 [Piper VB-760 数据角色](../FUEL_MODEL.md)和几何/重量/安装资料是否足够。已用的 65% 点继续属于校准，55%/75% 点继续属于同源留出。不能因启用新软件版本就重置这些角色。报告提出的其他飞机可作为后续候选，须匹配其构型，不能直接套用当前低翼模板。

首期不预先承诺整机误差已经小于某个百分比。先列误差预算、读图/条件不确定性和专业可接受范围，按结果逐项判定。没有独立数据的全尺寸桨或安装损失继续保留研究状态；若其敏感性足以改变方案优劣，比较结果应显示排序不确定或需要补充数据。

## 七、当前不作为充分实现要求的事项

| 事项 | 当前处理与理由 | 重新启动/完成条件 |
|---|---|---|
| 每轮全壳有限元、全机结构详细化 | 当前先做翼盒快速定尺寸和关键代表件复核。把高成本求解放进每轮会妨碍总体探索 | 快速模型与代表件偏差影响方案判断，或具体连接/开孔/局部区域成为控制项 |
| 全包线滑流、非线性失速、CFD/气弹/疲劳 | 本阶段先补影响 CG/尾翼和任务的概念级估算与覆盖诊断 | 明确任务超出已验证方法域，且简化方法不足以支持决策时专项立项 |
| 完整适航符合性 | 先明确参考条款和概念性能约束；无需在首次总体工具中实现全部认证流程 | 型号/审定基础与专业验证计划确定后另设工作包 |

| 一次性重排全部代码、重写全部历史报告 | 先修当前产品路径和高风险公共接口，减少迁移错误与无效工作量 | 被后续功能触及或出现明确维护瓶颈时迁移，测试保护兼容性 |
| 所有原生软件立即进入公共 CI | 需要二进制许可、可信分发、运行时间和机器资源安排 | 满足条件后逐工具接入；此前仍要求冻结版本本地原生验收，跳过不能算通过 |

## 八、验收与下一次评审的重点

下一次 V0.3.1 评审只看三类明确成果：**同一构型定义一致、任务可管理、当前结果可正确使用。** 提交问题最小复现、修改前后对照、相关自动测试和一组修复后的原生代表运行；性能调查用于确定 V0.3.2 的开销分解，不为文档评审重跑所有历史算例。

V0.3.2 在冻结物理模型的条件下检验提速是否引入误差；V0.3.3 再改变物理假设并分解结果变化。这样可以区分“同一模型算得更快”和“飞机模型改变后结果不同”。V0.3.4～V0.3.5 完成约束和使用流程后，以有限的入口条件转回本机载荷及结构质量闭环。
