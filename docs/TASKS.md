# 后台计算与结果选择

V0.3.1 将新建飞机主流程中的初步总体、几何、气动、配平、阻力、气动反馈、推进复算、推进闭环、三方案和公开总体任务接入同一个本地队列。Windows 为本期运行平台；原有梁、板和结构专项入口保留原来的独立调用方式。

## 日常操作

更新版本前，先等待队列完成，或用任务面板取消计算并确认结束；随后双击“关闭 WingDesignHub.cmd”，再双击“启动 WingDesignHub.cmd”，确认页面版本号为 V0.3.5。仅刷新浏览器可能仍使用旧 Python 服务已导入的模块。“关闭”脚本会终止界面服务及其后代进程，因此不要用它代替运行中任务的正常取消；意外中断后仍保留记录供重开和新建重算。关闭浏览器页面则不会退出本地服务。

1. 填写并确认需求，点击计算。页面立即显示提交结果，顶部“计算任务与历史”列出排队和计算中的任务。
2. 查看已用时间、当前迭代、质量与残差、正在计算的气动工况和心跳。页面约每 2 秒读取小型进度文件；完整原生任务仍可能需要数十分钟。
3. 可以切换页面或关闭浏览器。重新打开软件后从任务列表查看进度；明确点击“取消此任务”才请求停止。
4. 计算结束后点击“载入此任务结果”。“当前总体结果”可在初步、气动反馈和推进闭环之间选择；对应参数、最终几何、报告和归档选择一起更新。改变下一次计算的初值来源不会删除历史结果。
5. 已取消、失败或中断的记录可“恢复此任务需求以便修改”，也可“按原输入重新计算”。前者恢复需求表单（原分析选项仍在任务记录中），修改后重新确认；后者按原需求、来源和选项创建新任务，保留旧证据。重算复用有效缓存，但不从叶素或总体迭代内部续算。尚未生成结果的失败任务也可恢复需求。

任务“计算已结束”表示计算服务返回；工程状态另外列出约束满足、超限、域外、未收敛或求解失败。缺极曲线和模型越界保持原失败信息。旧结果没有最终三维预览网格时显示其自身构型图，并保留原 CAD 下载，不借用别次运行的几何。

工具设置可配置 AVL、XFOIL、OpenVSP、CalculiX，以及已有 Julia、项目环境和 CCBlade 包目录。“检查 Julia 与 CCBlade 实际加载”比对真实加载路径和版本；文件存在、导入成功和气动验证通过是三种不同状态。

## 服务接口

Python 使用 `wingdesignhub.jobs`：

```python
job = submit_job(root, "coupled", project, parent_run_id=seed_id, options=options)
state = get_job(root, job["job_id"])
cancel_job(root, job["job_id"])
# 已结束/取消的任务以原输入新建重算
new_job = retry_job(root, job["job_id"])
history = list_jobs(root)
```

CLI 提供 `job-submit --kind ... --input ... --run-id ... --options ...`、`job-status --job-id ...`、`job-cancel`、`job-retry` 和 `jobs`。原同步 `size/feedback/coupled/compare` 接口保留给开发和可控脚本，调用方负责等待；普通用户使用界面队列。直接同步脚本和其他工作区不共享此队列，不应另开重型批次与本机队列争抢资源。

任务只接受已注册的计算类型和经过 schema 检查的配置；不接受任意命令或代码。重复提交同一输入、选项、来源和源码的活动任务返回已有任务。完成后再次提交会产生新运行；修改过的需求仍须重新确认。

## 状态、进程和证据

状态依次为 `queued → running → completed/failed`；取消为 `cancel_requested → cancelled`；工作进程失联为 `interrupted`。进程退出尚未确认时保留 `cleanup_failed` 并阻止继续启动队列，不能先报告取消成功。

`local/jobs/<job_id>/` 保存请求快照、状态、逐进程事件、资源采样和日志。工程输出继续进入 `runs/<run_id>/`。后台调度器独立于 Streamlit 会话；同一项目默认串行。Windows Job Object 在子进程恢复执行前绑定所有权，关闭或终止该 Job 会回收所属进程树；PID 与创建时间共同用于存活核查。其他项目/任务的同名求解器不作为清理目标。[Windows 官方机制](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)

界面轮询使用独立片段，不在每次心跳重新执行整页与大包导出。[Streamlit fragment](https://docs.streamlit.io/develop/api-reference/execution-flow/st.fragment) 普通方案与完整原生证据现已分层，计算缓存按依赖身份复用。V0.3.2.1 三方案温缓存实测13.34 min，3 min目标未达到；详见对应验证记录。

排队前保存源码签名，启动和结束均核查。正式验证期间冻结源码；正在计算时修改代码会留下诊断，须以固定版本重新提交。任务目录、机器配置和原始计算数据只留本地，不入公开 Git。
