# 加速计算、缓存与原生审计

正常从“新建飞机方案”开始，确认任务后运行初步总体，再运行推进闭环。闭环设置中的“计算方式”默认使用加速计算：物理模型、离散、积分步长和收敛门槛不变，重复工况使用经校验的精确缓存，同一外形的 AVL 工况尽量复用原生矩阵。所有求解状态与约束照常保留。

需要方法核对时可选择“原生审计（逐次启动，耗时较长）”。这一选项关闭新增的几何、AVL 和 CCBlade 计算缓存及会话复用，保留已经校验的 XFOIL 极曲线缓存。无论选择哪一种，总体收敛后都执行原有非节点气动、直接螺旋桨及积分步长检查。界面不会通过删减检查来加速。

耗时应分四项理解：

1. 首次构建：该模型与输入尚没有相关计算缓存，需要真正调用求解器。
2. 温缓存：完全相同的原生输入及计算依赖已经计算过，读取并重新验证原始产物。改变工况或模型可能产生部分命中，不能统称全温缓存。
3. 原生审计：最终非节点等独立复算，用于检查表查询与真实求解的差异。
4. 归档：计算结束后的完整证据整理，以及用户选择的轻量/完整方案导出。

计算身份与完整源码审计记录分开。界面代码改变不会使无关计算缓存失效；相关 Python 模型、Julia 源码、数据表、翼型、求解器或选项改变会影响对应身份。当前按模块文件建立保守闭包，共享文件中的无关函数变化也可能触发重新计算。

缓存只接收已检查的成功产物，成员和哈希不符时明确报错，保留失败证据。它不会扩大极曲线、桨图和气动表的有效域，也不会将缺点填零或外推。`local/cache/computation` 保存新增计算缓存；验证脚本可在该目录使用独立命名空间测首次构建，不删除日常缓存。用户正常使用无需终端操作。

V0.3.2.1 允许复用完整求解、已核验的“有效点＋域外点”桨图批次：域外状态和原因原样保留，查询仍拒绝跨缺点。含求解失败的批次不进入缓存。阻力几何前处理也按精确几何、条带定位和工具身份复用；最终非节点原生审计照常执行。

历史方案保持可读。跨软件版本或计算身份改变时，历史结果可用于查看和对照，当前计算会生成新的运行记录。日常保存采用 V0.3.1-A 的轻量方案包，完整原生过程按需另存。
