# V0.2.7 推进与总体闭环

本版补齐“推进需用功率→发动机质量→携油/重心→几何/气动→任务”的反馈。`solve_design`仍是唯一外层求解器，`PropulsionFeedback`提供学科查询；初步总体、独立气动反馈和冻结飞机推进复算保留原入口。相同需求重新定尺寸和固定飞机更换模型分别报告。

## 日常使用与接口

在“新建飞机方案”完成初步总体后，点击“运行推进闭环总体计算”。默认2400 rpm、三叶合成桨和显式低负荷基础耗油策略；可以修改转速，或要求耗油图外严格拒绝。程序逐轮运行OpenVSP、AVL/XFOIL、FAST-GA和CCBlade，普通用户无需使用终端。该入口重新定尺寸并生成新记录，原方案保留。

结果包括设计起飞重量、实际装载、额定功率、发动机质量、携油/储备、翼面积/翼展、重心、匹配余量、耗油方法覆盖和收敛历史。“保存方案到本机”与`.wdh`导出携带父任务、原生证据及最终`.vsp3`。重开只查阅历史计算；重新运行另建记录。存档原始运行仍在本机时，也可从存档直接启动推进闭环。

Python：`coupled_service.run_coupled(project, root, seed_run_id, options)`。CLI：`coupled --run-id ID [--coupled-options options.json]`。`CoupledOptions`包含`aero: FeedbackOptions`、`propeller: PropulsionOptions`和`low_load_policy`，两者积分步长须一致。运行模式`overall_propulsion`；超限、失败和未收敛均返回非零CLI退出码。归档增加`coupled_record`参数或`--coupled-run-id ID`；`get_results`及`generate_report`沿用统一服务。

来源可为已收敛初步总体或气动反馈，须有同一已确认需求、输入及产物哈希。允许历史版本作为初值，但明确标注其版本；几何和气动在新版本重新求解，不把旧表冒充新证据。

## 每轮如何更新

1. 由当前设计质量和燃油需求确定翼面积、翼展、尾翼及油箱包络。规定重量固定设计值，上限模式求解后检查上限。
2. 用上轮额定功率运行FAST-GA部件重量；动力、机体、系统和不可用油各计一次，加规定载荷形成干质量/质量矩台账。
3. 生成当前OpenVSP外形，以及绑定该外形和燃油重心的质量/高度气动表。桨直径继承模板；仅在本次进程内，对完全相同的直径、速度/高度、叶片选项和模型数据复用轴向桨图。
4. 同一干质量下内迭代携油：用`T=D+mg sin(gamma)`在有效CCBlade图谱中反求总距和轴扭矩，按`P=QΩ`计算轴功率；额定发动机满足巡航、爬升和留空功率约束及原有2%定尺寸余量。任务按此发动机的RPM/高度能力和耗油图积分，更新实际携油，直到差小于1e−7 kg。
5. 把功率、燃油及质量台账交回原外层。重新计算的重量模型验证功率—重量耦合；采用原0.75松弛，连续三轮质量/燃油/功率/空重变化及功率—重量耦合小于1e−4，CG变化小于0.001MAC。质量闭合、重量上限、功率、携油容量和任务要求分别验收。

发动机额定功率40–400 kW是当前经验模型范围。连续功率定尺寸没有自动选择实际商品发动机。发动机质量来自FAST-GA原生安装重量方法；机身包络、桨直径和部件站位仍为可见模板参数，未宣称完成商品发动机的安装适配。机翼、尾翼、容量及CG随总体更新，结构重量回写留在V0.4.0。

## 耗油图与匹配口径

采用FAST-GA 1.4.0随包`FourCylindersAtmospheric.csv`及其原生`BasicICEngine.sfc_interpolator`，转速2200–2700 rpm、图内PME约8.0819–20.6281 bar。原生等效体积随额定功率缩放，扭矩坐标为`Q = PME × 1e5 × V_equivalent / (8π)`；这是上游缩放约定，非真实发动机排量测量。

CCBlade给出实际轴功率和扭矩，直接在原生扭矩/RPM图内查询g/kWh，转换为kg/kWh及kg/s。爬升采用上游富油因子1.15，其他空中段为1。高度按原生自然吸气关系影响可用功率；上游没有额外高度/温度耗油修正，本版不额外编造修正。发动机及桨以同一个指定RPM匹配，记录推力、总距、轴功率、扭矩与可用扭矩余量。

| 任务区域 | 方法标识 | 处理 |
|---|---|---|
| 扭矩/RPM在图内 | `native_engine_sfc_map` | 原生插值，显式混合比因子 |
| 空中低于耗油图下限 | `engine_map_low_load_base_bsfc` | 默认采用方案基础BSFC，单列油量；`reject`策略返回域外诊断 |
| 滑行与起飞地面段 | `engine_map_ground_base_bsfc` | 沿用10%/90%额定功率、各300 s/30 s的明确估算；没有地面桨匹配 |
| 高于耗油图上限、RPM越界 | 明确错误状态 | 拒绝外推或裁剪；保留数值和边界 |

该入口覆盖原`constant_bsfc`或`piper_economy_reference`任务耗油选择，基础BSFC仅用于上述显式区域。原选择仍用于初步总体，便于比较，不与新图相加。储备继续按平均巡航油耗单独携带，不加入已飞航程/航时。方法油量之和须等于总可用燃油。

## 验证与数据角色

- `tests/test_engine_fuel.py`：330个节点、独立P/Q/油耗单位、功率缩放、富油因子及域外行为；测试图内一致性不等于独立物理验证。
- `tests/test_propulsion_feedback.py`：用明确标识的解析替代学科检查真实外层求解器，覆盖三重量×四任务、需求传递、不可行与不收敛。原生整机另行验证。
- `scripts/validate_engine_fuel.py`：固定SHA的[FAST-GA v1.4.0官方测试](https://github.com/supaero-aircraft-design/FAST-GA/blob/v1.4.0/src/fastga/models/propulsion/fuel_propulsion/basicIC_engine/unitary_tests/test_basicIC_engine.py)原文件执行，并独立核对发动机安装系数与lb/kg换算。
- 官方测试原文件有本地缓存时复用并核对SHA；新检出没有该缓存时从上述固定v1.4.0地址获取并核对SHA，不要求复制开发机的私有工作目录。
- `scripts/validate_coupled.py`：本机完整闭环、真实发动机质量/携油/几何传递、非节点气动/桨图直接复算、步长减半、48/96径向检查、[CCBlade官方APC案例](https://flow.byu.edu/CCBlade.jl/stable/tutorial/)、档案与报告。`--resume`核查源码/适配脚本一致后复用已完成记录。

发动机图是上游通用数据；APC小桨是官方公开案例及其试验对照；当前全尺寸桨是独立合成几何。没有用这些案例拟合本机发动机或桨，也没有获得本机独立试验精度。轴向均匀入流、理想恒速变距、桨尖Mach≤0.75、XFOIL原始剖面域、小迎角配平和单向阻力叠加等边界继续生效。具体型号混合比/油门标定、安装/滑流、起降距离及结构回写按后续路线推进。

官方发动机测试还包含零来流速度下接近零的上游推力比耗油输出。本版保留这一项作为原文件的数值回归，地面耗油采用另列的基础功率/时长估算；它没有提供地面发动机—桨匹配的物理验证。
