# WingDesignHub 版本路线图

更新：2026-11-18。**V0.3.3 软件接口和本轮有界构型核查完成，具体机型独立物理验证保持打开。** 分项站位/安装角、公开基准、固定对照和重新定尺寸已形成证据。V0.3.2.1的三方案13.34 min与性能受限状态保持；下一节点V0.3.4一级约束。见[本版验证](VALIDATION_V0.3.3.md)。

目标保持不变：**少量任务需求 → 确认任务与可见假设 → 正向定尺寸和重量/燃油/性能迭代 → 初步技术参数、约束余量及方案比较。** 常规亚声速、金属结构、活塞螺旋桨单发飞机优先，逐步覆盖 AAA 十模块，AI 在确定性工程内核之后接入。

本文件是当前节点顺序和验收的唯一依据。[原路线图快照](history/ROADMAP_THROUGH_V0.3.0.md)保留历史判断，其中旧的“下一节点”不再代表当前计划；[PROGRESS](PROGRESS.md)保留每轮真实开发和验证记录。

## 当前成果与此次调整

V0.3.0 已实现需求驱动总体、OpenVSP 几何、AVL 配平/XFOIL 阻力、发动机/CCBlade 推进与任务反馈，以及增强三方案、方案卡和保存重开。软件阶段已有 399 项本地回归及 27 项原生三方案检查；三方案实测约 160 min，完整包 537.80 MiB。增强整机独立物理验证、专业签署及结构定尺寸质量替换尚未完成。[阶段验证](VALIDATION_V0.3.0.md)

评审发现的关键缺口包括：尾翼跨模块参数冲突；部件站位、支柱阻力、速度安排及推进模型缺少目标机型依据；起降与重心/尾翼一级约束未齐；原生计算与归档开销过大；任务管理及当前结果显示不够可靠。详见[评审回复书](reviews/REVIEW_RESPONSE_V0.3.0.md)的 RV-01～RV-33。

因此先完成有限的一轮总体模型与产品流程改进，再进入本机载荷和结构反馈。既有结构算例保留为方法验证资产，不再默认占据主设计入口。提速先在冻结物理模型下验证，物理假设调整另做差异归因；不同时改动后只比较最终油量。

## 近期检查与停止条件

V0.3.1 的工作包 W1～W5、前十工作日安排及通过条件见[执行计划](reviews/NEXT_PLAN_V0.3.1.md)。正式代表计算与完整回归保持串行；记录之前已有结果和新计算的区别。本版按该计划验收，未启动下一版长计算。

V0.3.2 在修正后的同一物理模型上做快速化，先冻结以下拟定预算：

- 非节点总 CD 相对差≤2%；任务燃油/安装功率差≤1%；起飞质量差≤0.5%。近零量用独立绝对容差。保留最终原生配平残差 1e-5 和已有账目、最终收敛要求；临界可行性须原生核验或明确待核。
- 同机同条件三方案核心计算至少加速 5 倍为阶段门槛；已建表模板三方案≤3 min 为产品目标。冷建表、最终原生审计与温缓存查询分别报告；未达到目标则如实保留性能受限状态。
- 核心输入/结果/诊断/manifest 目标<5 MiB，可移植工程包（含必要表、最终几何和报告）初始预算≤20 MiB；完整调试证据另导出。实际容量及包内范围分别列示，旧包和历史运行保留。
- 按有限模板试点；首轮极曲线失败专项限定 2 个工作日实验。达不到精度或域覆盖时保留原生路径和缺点诊断，不为了速度静默退回经验公式。

这些是事先设定的内部工程要求，不是当前已达到的指标，也不是对真实飞机的物理精度承诺。若需调整，先以独立证据说明原因、更新计划后再验证，不在结果出来后降低门槛把失败改成通过。

V0.3.2 代表任务的冷计算总加速为 3.10 倍、温缓存为 11.10 倍，14 轮迭代的主要参数与旧结果一致；新包 2.04 MiB。单方案成绩不关闭三方案门槛。进入 V0.3.3 前安排一次有边界的性能复核：固定现有三方案输入，逐方案保存，串行记录首次构建/温缓存/原生审计及实际瓶颈；重点核查已实测的极曲线精确请求补算、混合有效/域外桨图的重复批次和阻力几何前处理，只对已证实重复调用作小范围补丁。该复核限定一轮实验与复测，性能仍受限时保留原门槛和限制，明确评审后再安排后续产品节点，不自行降低标准或无限扩展通用框架。

V0.3.3 先做固定构型对照，再做需求驱动重定尺寸。数据使用前确定条件及校准/留出/独立角色；引入新物理假设要与提速误差分开比较。第二架独立飞机和全尺寸推进试验缺失不阻止受限研究，但影响方案结论的缺口须显式显示。

V0.3.5 是前述主流程的收口，不是另起一轮大规模 UI/架构项目。进入 V0.3.6 要有一致构型、可用运行流程、明确的载荷/配平状态与质量/CG台账，并确认结构布局/材料/支承的来源或研究假设。**不等待全部 CFD、全部历史报告迁移、第二架整机验证或所有工具公共 CI。**

## 十模块与方法的延续

重量、几何、气动、推进、性能继续沿同一总体求解器推进；基本 CG/纵向尾翼控制前移到 V0.3.3～V0.3.4；载荷与机翼结构在 V0.3.6～V0.4.0 接入质量回写；其余操稳、动力学、成本及其他主要部件在 V0.5.0 补齐。十模块均须提供可调用计算、输入检查、公开依据及验证案例。

固定工具路线维持 FAST-GA/OpenMDAO、OpenVSP、AVL/XFOIL、CCBlade、OpenAeroStruct/CalculiX；VSPAERO 用于后续动力增量，python-control 与已有成本方法按模块需要接入。优先集成和共享数据契约，不重新开发所有求解器。快速模型参与每轮迭代，原生/有限元用于独立点和代表状态复核。

V0.3.1 已取得同输入原生基线：温极曲线缓存下单方案 57.75 min，其中 AVL 690 次调用累计 49.13 min；完整方案包 171.28 MiB。V0.3.2 优先核查 AVL 调用复用及归档去重，以相同缓存口径比较数值误差和性能。整个平台交付日期仍依据数据可得性和专业复核修订；原 5～7 个月是建设初期估计，不作为已证实的剩余工期。

V0.3.1-A 数据治理专项于 2026-11-18 完成软件验收，已执行日志限额、分级归档、内容去重及可恢复初步整理；验收见 [专项报告](VALIDATION_V0.3.1-A.md)。该专项前移 V0.3.2 的存储工作，不改变后续物理/结构节点顺序。

V0.3.2.1 已完成上述一次限定实验与复测，具体未关闭项和容量证据见本版验证记录。后续按 V0.3.3 处理构型依据和同条件单发基准；性能问题作为保留项，不默认新增性能微版本，也不将物理模型调整与提速差异混算。


V0.3.3 收口后，V0.3.4 先建立未计算约束的显式状态，再接近静态推进/起降、装载CG与纵向约束、域内速度安排。Piper总长代理、设备/机油口径、真实固定距桨、机身/动力力矩和2412/偏舵翼型数据仍为开放输入；不凭本版误差诊断带关闭这些条件，也不等待全部高保真数据才接工程流程。
